Exact rules, sources and Inspect logs

The baseline implements the two-target, one-resource, fixed-punishment subcase of Blocki et al., Audit Games, §2, with its no-violation option. The reward profiles are our finite-type extension using the information structure of Paruchuri et al., AAMAS 2008. These demo payoff numbers are ours, not a published experimental dataset.

The threshold study uses unchecked rewards (0.2, 0.1) or (0.8, 0.7), with penalty 0.5. The information study uses (0.8, 0.1) or (0.2, 0.7), with penalty 0, so knowing which target the attacker values can change the best defense. In each revealed/hidden pair the actual rewards are identical. In both instances, unchecked rewards average 0.5 at A and 0.4 at B; checked rewards before punishment are −0.5 and −0.6. Defender rewards are −1 / −1.2 unchecked and −0.1 / −0.2 checked. The defender always pays 0.1 × punishment, including after abstention. Penalties are not transferred to the defender. Exactly one target is checked.

The exact solver covers continuous checking allocations and finite reward profiles. It reports favorable and unfavorable attacker ties, including unattained limits. It does not jointly optimize the punishment level or solve general continuous reward distributions.

Local experiment runner: python audit_experiment.py runs/audit-check --study information, after installing pip install '.[inspect]'. View native traces with inspect view --log-dir runs/audit-check. This command uses scripted mock models. The separate study runner supports budgeted live Inspect collection. The threshold study sweeps only checking chance at fixed rewards and penalty; the information study holds these rewards and penalty fixed, compares revealed/hidden trials, and measures the defender’s chosen checking chance. Browser rounds are local demos, not Inspect experiments; they are not uploaded. No live validation is claimed.
